## Overview

Omniference is a Rust multi-protocol inference engine providing a unified API for AI providers (Ollama, OpenAI, etc.).

## Project Structure

```
src/
├── lib.rs           # Public API exports
├── main.rs          # Binary entry point
├── adapter.rs       # ChatAdapter trait definition
├── adapters/        # Provider adapters (Ollama, OpenAI); openai_endpoints.rs = shared OpenAI REST endpoints beyond chat; system_one.rs = System One decisions; dialects/ = vendor dialects of the Chat, Responses and Anthropic Messages adapters; request_rules.rs = vendor profile request rules
├── image.rs         # Shared image-provider transport and response utilities
├── upstream.rs      # Shared upstream error response handling (status parsing + redaction)
├── router.rs        # AdapterRegistry + Router
├── service.rs       # OmniferenceService (provider management)
├── server.rs        # OmniferenceServer (HTTP + Axum)
├── engine.rs        # OmniferenceEngine (high-level API)
├── types/           # Core types (Message, ChatRequestIR, etc.); modalities.rs = non-chat IRs (embeddings, rerank, speech to text, text to speech, decisions)
├── middleware/      # Middleware chain
├── skins/           # Protocol skins (OpenAI-compatible, etc.)
│   ├── mod.rs       # Skin trait + SkinErrorHandler trait
│   ├── context.rs   # SkinContext (shared state)
│   ├── openai.rs    # OpenAI-compatible skin implementations
│   ├── openai_media.rs # OpenAI embeddings and images routes
│   ├── anthropic.rs # Anthropic Messages skin (/api/anthropic/v1/messages, /models) + AnthropicErrorHandler
│   ├── decisions.rs # OpenAI decisions and System One routes
│   └── openai_audio.rs # OpenAI audio routes (transcriptions, translations, speech)
├── stream.rs        # Streaming utilities
├── catalog/         # Data-driven model metadata, pricing, overrides, refresh; providers.rs = vendor profiles
└── config/          # Configuration handling
```

## Architecture: Skins ↔ Adapters

The core architecture uses two complementary traits:

```
External API → [Skin] → ChatRequestIR → [Adapter] → Provider API
    (inbound)                               (outbound)
                         ↘ [Catalog] metadata/pricing enrichment
```

### `Skin` trait (`skins/mod.rs`)

Converts **external API formats** to internal IR (inbound):

```rust
pub trait Skin: Send + Sync {
    type Request: DeserializeOwned + Send + Clone;

    fn external_to_ir(req: Self::Request, model: ModelRef) -> Result<ChatRequestIR>;
    fn error_handler() -> &'static dyn SkinErrorHandler;
    fn skin_id() -> &'static str;
}
```

**Implementations:**

- `OpenAIChatSkin` - `/v1/chat/completions` endpoint
- `OpenAIResponsesSkin` - `/v1/responses` endpoint
- `AnthropicMessagesSkin` - `/api/anthropic/v1/messages` (`Request = serde_json::Value`, the raw body); also `GET /api/anthropic/v1/models`
- `OpenAIEmbeddingsSkin` - `/v1/embeddings`; `OpenAIRerankSkin` - `/v1/rerank`; `OpenAIDecisionsSkin` - `/v1/decisions`; `SystemOneSkin` - `/v1/systemone`; `OpenAIImagesSkin` - `/v1/images/generations` (JSON) and `/v1/images/edits` (multipart); `OpenAIAudioSkin` - `/v1/audio/transcriptions` and `/v1/audio/translations` (multipart), `/v1/audio/speech` (JSON). These do not implement `Skin` (it is chat-specific); see Non-chat model types below.

### `ChatAdapter` trait (`adapter.rs`)

Converts **internal IR** to provider API and executes (outbound):

```rust
pub trait ChatAdapter: Send + Sync {
    fn provider_kind(&self) -> ProviderKind;
    async fn execute_chat(&self, ir: ChatRequestIR, cancel: CancellationToken) -> Result<Stream>;
    async fn discover_models(&self, provider_name: &str, endpoint: &ProviderEndpoint) -> Result<Vec<DiscoveredModel>>;
    async fn execute_image(&self, request: ImageRequestIR) -> Result<ImageResponse>;
    async fn execute_embeddings(&self, request: EmbeddingRequestIR) -> Result<EmbeddingResponse>;
    async fn execute_rerank(&self, request: RerankRequestIR) -> Result<RerankResponse>;
    async fn execute_decision(&self, request: DecisionRequestIR) -> Result<DecisionResponse>;
    async fn execute_transcription(&self, request: TranscriptionRequestIR) -> Result<ByteStreamResponse>;
    async fn execute_speech(&self, request: SpeechRequestIR) -> Result<ByteStreamResponse>;
    async fn discover_image_models(&self, provider_name: &str, endpoint: &ProviderEndpoint) -> Result<Vec<DiscoveredModel>>;
}
```

**Implementations:**

- `OpenAIAdapter` - OpenAI-compatible providers
- `OpenAIResponsesAdapter` - OpenAI Responses API
- `OpenRouterAdapter` - OpenRouter gateway: chat runs through OpenRouter's Responses API (`OpenAIResponsesAdapter::execute_with` with `OpenRouterDialect`); discovery and image generation are its own
- `AnthropicAdapter` - Anthropic Messages API
- `GeminiAdapter` - Google Gemini Interactions API, including native Gemini image generation and editing
- `SystemOneAdapter` - TypeSafe-style System One servers (`ProviderKind::SystemOne`, decisions only)

```bash
# All tests and targets (skip live API)

```

### Adding Tests

- Use `common::` helpers for test data
- Live tests: check `common::should_skip_live_tests()` first
- New adapter tests → `tests/unit/adapters.rs`
- Adapter tests that need an upstream use `common::upstream::FakeUpstream` (scripted replies with byte-level chunking, delays, disconnects, stalls, and captured requests); do not hand-roll mock servers.
- Streaming adapters must be added to `tests/unit/stream_rechunking.rs`, which asserts identical events under any transport chunking, including splits inside UTF-8 characters; relayed byte streams (speech to text and text to speech SSE) are covered in its `byte_stream_relay` module.
- Provider/protocol behavior that can be expressed as a saved request/reply pair belongs in `tests/cases/<inbound>/<provider>/<scenario>/`, run by `tests/unit/case_matrix.rs` with `insta` snapshots; see the Case matrix section of `tests/README.md`. Every model type with an HTTP route has an inbound there (`openai_embeddings`, `openai_rerank`, `openai_decisions`, `systemone`, `openai_images`, `openai_image_edits`, `openai_transcriptions`, `openai_speech` next to the chat inbounds `openai_chat`, `openai_responses` and `anthropic_messages`), listed in the runner's `INBOUNDS` table with the providers that implement it; a new type adds its inbound, a direct path (`external_to_ir` + adapter) and cases. The live matrix covers the OpenAI chat inbounds only.
- Live provider checks: real providers are the `[[target]]` entries of `tests/live_targets.toml` (`id`, `adapter` case directory, `base_url`, `key_env`, `model`, optional `vendor` passed as `catalog_provider_slug`; env overrides `LIVE_MODEL_<ID>`/`LIVE_BASE_<ID>`), and several targets may share an adapter. `case_matrix_live` (ignored, `CASE_LIVE=1`) replays the saved chat cases on every target of their adapter (cases whose `case.toml` names a `vendor` only on that vendor's targets) with structural assertions instead of snapshots (the per-scenario table lives in `tests/unit/case_matrix_live.rs`), labelled `<inbound>/<target>/<scenario>`; `CASE_RECORD=1` additionally writes the real replies back into the case folders (never `.snap` files), only from the first target in the file that runs the case. Vendor scenarios are named `<vendor>_<scenario>` and get the check of `<scenario>`. The catalog sets expectations: for a model with the `tools` or `reasoning` capability, tools without `tools` and a reasoning effort outside its models.dev `reasoning_options` must be a clean 4xx (the effort rule is skipped on `openrouter`, which maps efforts); a provider that accepts such a request, or rejects one the catalog allows, fails as "wrong catalog entry or missing vendor profile". `CASE_MODEL=<target id>/<model>` (new-model testing) runs only that target with that model on every case, and the model's catalog type (`DiscoveredModel::model_type`) picks the inbounds (only `chat` has live checks). `tests/integration/live_reasoning.rs` runs two-turn reasoning + tool-call round trips (capped at 4096 output tokens) through the real server routes via `common::reasoning_flow`; its tests are `#[ignore]`d and need `LIVE_REASONING=1`, so plain `cargo test` never spends money. Both reach the provider through `FakeUpstream::proxy` (recording passthrough) and skip without keys; offline coverage of the proxy and flow engine is in `tests/unit/upstream_proxy.rs`, `tests/unit/reasoning_flow.rs` and the `offline` module of `case_matrix_live.rs`. Credentials come from environment variables only (`common::live`); never print, snapshot or record them.
- Property tests use `proptest`; commit files under `proptest-regressions/`.
- New type tests → `tests/unit/types.rs`
- Keep tests in `tests/unit/` or `tests/integration/`; do not add test modules to production source files.

## Key Conventions

- **Async**: Tokio runtime everywhere
- **Errors**: `anyhow::Result` for apps, `thiserror` for library
- **Adapters**: Implement `ChatAdapter` trait for new providers
- **Gemini**: Use the stable, stateless `/v1/interactions` API with `store = false`; preserve provider tool-call IDs. Function_call steps without a preceding Gemini thought carry the `skip_thought_signature_validator` placeholder because Gemini 3.x rejects unsigned calls. Signature-only thought steps (no summary text) are captured as Gemini reasoning blocks and replayed with their signature. Gemini image generation and editing use Interactions; Imagen is not supported.
- **Images**: Image generation and editing route through `Router::route_image`; adapters opt in through `execute_image` and may augment discovery through `discover_image_models`. `OmniferenceService::image` preserves `InferenceError` categories and records usage through `record_unit_usage`. HTTP: `POST /images/generations` and `/images/edits` under both `/api/openai/v1` and `/api/openai-compatible/v1`; edits get their own body limit (`ServerSecurityConfig::max_image_body_bytes`, 25 MiB) layered on the route. `ImageRequestIR::raw_request` keeps the client's JSON body or multipart text fields and `ImageResponse::raw` the upstream JSON; OpenAI and openai_compat (`adapters/openai_endpoints.rs`) forward the raw fields with `model` rewritten and the set typed IR fields (`prompt`, `options`) written over them (`n` defaults to 1 only without a raw request; no model-ID-based `response_format`), send every edit image (`image[]` when more than one) plus `mask`, and the skin relays `raw` unchanged. URL-only data items (including `b64_json: null`) are left out of `images` and stay in `raw`. Providers that return one unmasked image (OpenRouter, Gemini) reject `n > 1` and masks via `image::require_single_unmasked`; the skin rejects `response_format: "url"` for providers other than OpenAI/openai_compat.
- **Non-chat model types**: Each type has its own IR in `types/modalities.rs`, a default-unsupported `ChatAdapter::execute_*` method (`AdapterError::Invalid`), `Router::route_*` (strips the provider prefix), `OmniferenceService::*`/`OmniferenceEngine::*`, and an OpenAI skin route under both prefixes. `SkinContext` runs them through the service when it has one (usage accounting) and straight through the router otherwise. Every IR keeps the raw client request; OpenAI-family adapters forward it with `model` rewritten and the set typed IR fields written over it (so hosts can change the IR after `external_to_ir`), and relay the raw upstream JSON. Embeddings: `POST /embeddings`, `prompt_tokens` → input tokens. Rerank: `POST /rerank` (Jina/Cohere v1/vLLM body: `query`, `documents` as strings or objects, `top_n`, `return_documents`) forwarded to `{base}/v1/rerank` by openai_compat only (OpenAI has no rerank API; Cohere v2 lives at `/v2/rerank` and is not supported); `usage.total_tokens` (else vLLM's `meta.billed_units.total_tokens`, Cohere `meta.billed_units.input_tokens` or `meta.tokens.input_tokens`) → input tokens, `usage.search_units` or Cohere `meta.billed_units.search_units` → `searches`. Speech to text and text to speech are below. Model kinds are capabilities (`EMBEDDINGS`, `SPEECH_TO_TEXT`, `TEXT_TO_SPEECH`, `RERANK`, `DECISION`, `SYSTEM_ONE`, plus `IMAGE_GENERATION`/`IMAGE_EDITING`) from the models.dev `type` field (`embedding`, `reranking`, `transcription`, `speech`, `image`), checked-in TOML overrides under `catalog/overrides/` (for models models.dev lacks or misdescribes, such as OpenAI's Images API models that models.dev lists with text output), or an `Embeddings`/`Image` output modality; never from model IDs. Every route checks `DiscoveredModel::supports(ModelOperation)` through `SkinContext::resolve_model_for` and answers 400 `model_not_supported` for a model of another kind (a chat model on `/embeddings`, an embedding or image-only model on chat); a model with no kind facts at all (no kind capability, tools or reasoning, typical for self-hosted models missing from the catalog) is allowed everywhere. `/models` entries carry a primary `type` (`DiscoveredModel::model_type`, one of `MODEL_TYPES`: the models.dev names `chat`, `embedding`, `reranking`, `transcription`, `speech`, `image`, plus `decision` and `systemone`) and a `capabilities` array of codes; `?type=` keeps models of that type (unknown → 400 `invalid_type`). `OpenAIModel` never deserializes `type`/`capabilities` from upstream model lists (providers such as Mistral send their own shapes there). A malformed provider body on embeddings/images is `AdapterError::Http` (502), never a client 400; embedding items without `index` take their position. An image generator with tools or reasoning and text output is `chat`; a model without kind facts defaults to `chat`.
- **Decisions and System One**: `POST /decisions` (OpenAI, `OpenAIDecisionsSkin`) and `POST /systemone` (TypeSafe System One, `SystemOneSkin`) under both prefixes, `ModelOperation::Decision`, both into one `DecisionRequestIR` (input content parts or OpenAI messages, ordered questions `Predicate`/`Choice`/`Score`/`Box`, `protocol` tag, raw request) and out of one `DecisionResponse` (answers in question order: `Predicate`/`Choice`/`Score`/`Box`/`Refusal`, `protocol` of `raw`). A request whose protocol the provider speaks is relayed raw with only `model` rewritten (OpenAI `prompt_cache_*`/`safety_identifier` pass through); otherwise the adapter renders the IR, and the skin relays `raw` only when the response protocol matches its own and renders from the answers otherwise. OpenAI and openai_compat post to `{base}/v1/decisions`; `SystemOneAdapter` (`ProviderKind::SystemOne`, bearer auth, configurable base URL for TypeSafe, DigitalOcean or self-hosted servers) posts to `{base}/v1/systemone`, discovers through `GET /v1/models` (bare array or `models`, `name` or `id`) with the `SYSTEM_ONE` capability, turns image parts into `assets` with generated `image-<uuid>` references and sends `TypeSafe-Danger-Zone-Images: true` only when assets or `box` questions are present. System One keys questions by name (unnamed ones by position; duplicates are 400) and boolean choice values as `"true"`/`"false"`, mapped back on the way out; predicate criteria travel to OpenAI as an `input_json` instructions part and structured descriptions as compact JSON text. 400 rejections: `box` on OpenAI, OpenAI conversations/tool items or hosted image URLs on System One, images for a model without image input, and System One asset references inside longer strings, objects or criteria for providers other than System One. Usage: input tokens with OpenAI `cached_tokens`/`cache_write_tokens`; output tokens are free and never recorded. `DECISION` is additive like image generation (gpt-6-luna keeps chat via a catalog override that repeats its chat capabilities), while `SYSTEM_ONE` models are decision-only; Jev pricing lives in `catalog/overrides/typesafe/` (provider slug `typesafe`). Errors render like every other skin (OpenAI error body), and `upstream::http_error` reads FastAPI `detail` strings as the message.
- **Speech to text and text to speech**: `POST /audio/transcriptions` and `/audio/translations` (multipart, `TranscriptionRequestIR`) and `POST /audio/speech` (JSON, `SpeechRequestIR`), under both prefixes; the two multipart routes get their own body limit (`ServerSecurityConfig::max_audio_body_bytes`, 25 MiB). Model kinds: `ModelOperation::SpeechToText`/`TextToSpeech`. Both return a `ByteStreamResponse`: the upstream content type plus a lazy `ByteStreamEvent` stream (`Data` bytes relayed unchanged, `Usage` reports, a final `Error`), so JSON, text (`srt`, `vtt`, `text`), audio and SSE (`stream: true`, `stream_format: "sse"`) all relay as the provider sent them. SSE bodies are relayed one complete event at a time (re-framed as `event:`/`data:` lines), so a mid-body failure never lands inside a forwarded event, and an in-band error event (`error` object or `type: "error"`) ends the stream as an `Error` instead of being relayed raw. A non-success status on a streamed call reads its error body under the endpoint timeout too. The multipart raw fields keep repeated names as arrays and are forwarded one part per item (`timestamp_granularities[]`, `include[]`); the audio keeps the client's file name and media type. Streamed calls (speech always, transcriptions with `stream`) use `adapter::provider_headers` without a total timeout and `next_chunk` for the idle gap; non-streamed transcriptions keep the total timeout. Usage: transcription token usage (`input_token_details.audio_tokens` → `input_audio_tokens`, the rest input tokens) else `usage.seconds`/`duration` → `input_audio_seconds`; speech counts `input_characters` always and, from `speech.audio.done`, input tokens and output tokens as `output_audio_tokens`. `OmniferenceService::transcription`/`speech` look up pricing before the call and record usage once at end (`Done`), first error (`Error`) or drop (`Dropped`) through `UnitUsageRecorder`; header-reported provider cost stays authoritative. The skin turns a mid-body failure into an `openai_stream_error_frame` on SSE bodies and cuts other bodies off. A non-streamed speech reply from gpt-4o-mini-tts carries no tokens, so it is recorded without cost.
- **Unit usage and pricing**: `UsageBreakdown` also counts `input_audio_seconds`, `input_characters`, `requests` and `searches`; `ModelPricing`, `PricingRates`, `ContextTier`, `ResolvedRates` and `RawCost` carry `per_audio_second`, `per_character`, `per_request` and `per_search` in USD per unit (all `#[serde(default)]`). `cost::compute` adds unit charges to the prompt cost; a missing audio-second, character or search rate is `CostSkip::MissingRate` (a missing character rate only when the provider reported no tokens: token-priced speech models have none and their characters are then informational), while a missing request rate charges nothing (every non-chat call reports one request; chat reports none). OpenRouter's `request` price maps to `per_request`. `OmniferenceService::record_unit_usage` records non-chat usage: `terminal_usage` once, then provider-reported cost (`ProviderReported`) or catalog cost (`Done`) via `record_with_context`, or `record_usage` with zero cost when pricing is missing.
- **Adapter resolution**: Register protocol-wide adapters by `ProviderKind`; use `AdapterRegistry::register_for_provider` only when one provider needs a specialized adapter. Routing checks the exact provider registration before falling back to its kind.
- **SSE parsing**: Adapters feed raw response bytes to `sse::SseParser`; never decode transport chunks to strings before parsing. The parser follows the WHATWG event-stream grammar (`\n`, `\r\n`, `\r` line endings, comments, BOM, multi-line data).
- **HTTP transport**: Provider adapters and catalog clients use `adapter::shared_http_client()`; `adapter::provider_request`/`provider_url` apply endpoint extra headers and the total timeout for non-chat REST calls so connection pooling, connect timeouts, and transport policy stay centralized. Provider `timeout` is applied through `adapter::send_with_timeout`/`next_chunk`: for streaming chat it bounds only time-to-response-headers and the idle gap between body chunks (expiry is `AdapterError::Timeout`, rendered as a `timeout` stream error mid-stream), never total stream duration; non-streaming chat, discovery, image, embedding and non-streamed transcription calls keep a total timeout, while speech and streamed transcriptions are bounded like streaming chat. Long generations should use streaming, since non-streaming responses send no bytes until done and intermediate proxies (nginx/ALB/Cloudflare idle timeouts ~60-100s) or client SDK timeouts may cut them.
- **Skins**: Implement `Skin` trait for new external API formats
- **OpenAI Chat compatibility**: `OpenAIChatSkin` retains the original typed Chat Completions request in `ChatRequestIR::openai_chat_request` for lossless forwarding. `OpenAIAdapter` emits raw completion/chunk stream events alongside normalized events so the OpenAI skin can preserve multi-choice output, logprobs, audio, annotations, finish reasons, usage, and provider metadata.
- **OpenAI Responses compatibility**: `OpenAIResponsesSkin` retains the original raw Responses request in `ChatRequestIR::openai_responses_request` for lossless and forward-compatible forwarding. `OpenAIResponsesAdapter` emits raw response objects and named SSE events alongside normalized events; the Responses skin must relay those raw values instead of reconstructing protocol output. For non-Responses providers the skin maps `instructions`/`tools`/`tool_choice`/`text.format`/`include`/`function_call` I/O into the IR and synthesizes the Responses event protocol (`response.created`, output-item/text/reasoning/function-call events, `response.completed`/`response.incomplete` with usage) from neutral stream events.
- **Anthropic Messages compatibility** (Claude Code's gateway protocol: forward `anthropic-version`, `anthropic-beta` and the body unchanged, never allowlist betas): `AnthropicMessagesSkin` keeps the raw request plus the client's `anthropic-version` and every `anthropic-beta` header value (joined with `,`) in `ChatRequestIR::anthropic_messages_request` (`AnthropicWireRequest`). `AnthropicAdapter` then sends that body with only `model` and `stream` rewritten and those headers (`anthropic-version` defaults to `ANTHROPIC_VERSION`); every Anthropic body (raw or built) goes out with top-level keys ordered `system`, `tools`, the rest, `messages` (`messages_wire_body`; `serde_json` maps sort keys, and Vertex AI only hits the prompt cache reliably in that order; covered by `anthropic_wire_key_order` in `tests/unit/adapters.rs`), and emits `StreamEvent::AnthropicEvent`/`AnthropicMessage` raw values next to the normalized events; the skin relays the raw values (an upstream `error` event once, never twice). Other providers get the request through the IR (system blocks and `role: "system"` messages → System, `tool_result` → Tool message named by `tool_use_id`, `thinking` → reasoning: empty signature = unsigned, `omn1.` envelope = another provider's block, else Anthropic signature; `thinking.enabled` budget → `budget_tokens`, `adaptive` + `output_config.effort` → effort, adaptive without effort → provider default; `output_config.format` → JSON schema), and server tools or unknown content blocks are a 400 there. Anthropic providers get the raw body only: the skin builds no IR messages or tools for them, so nothing in the body is rejected. A stream that ends before `message_stop` (Anthropic adapter) or without `Done` (skin) is an error, never a completed message. The skin renders the event protocol from neutral events (`MessageRenderer`; tool arguments go out as one `input_json_delta` at `ToolCallEnd`; non-Anthropic reasoning blocks become thinking blocks whose signature is the `omn1.` envelope) and builds non-streaming messages by folding those events. Errors use the Anthropic body `{"type":"error","error":{"type","message"}}` with the same statuses as the OpenAI skins (`skins::inference_error_status`); `determine_skin_from_path` picks `AnthropicErrorHandler` for `/api/anthropic/`. Bearer auth also accepts `x-api-key` on `/api/anthropic/` routes only. The adapter emits the upstream `request-id` header as `StreamEvent::UpstreamRequestId` before any other event; for Anthropic providers the skin reads that first event and sends `request-id` on the response (stream and non-stream). `/api/anthropic/v1/messages` has its own body limit (`ServerSecurityConfig::max_messages_body_bytes`, 32 MiB, Anthropic's own limit) because Claude Code requests outgrow `max_body_bytes`. Not implemented: `/v1/messages/count_tokens` (404, Claude Code then estimates locally) and `anthropic-ratelimit-*` headers (they describe the gateway's account). The `anthropic_messages` case inbound has no live checks (`is_live_inbound` in `case_matrix_live.rs`).
- **In-stream provider errors and usage variants**: openai_compat surfaces an HTTP 200 SSE `data: {"error": ...}` frame as `StreamEvent::Error` (code `upstream_error`, so skins keep rendering the generic mid-stream error text), reads `delta.reasoning`/`message.reasoning` like `reasoning_content`, and maps DeepSeek `prompt_cache_hit_tokens` onto `cached_tokens` only when `prompt_tokens_details.cached_tokens` is absent. The Responses adapter emits usage and the reasoning blocks of `response.output` from `response.incomplete` like `response.completed`, emits non-streamed reasoning item text as `ReasoningDelta`, and accepts the nested `{"type":"error","error":{...}}` stream error form (flat fields stay as fallback) with a string or numeric `code` (OpenRouter sends HTTP status numbers), as do `response.error` and `response.failed`. The Responses renderer maps `FinishReason::ContentFilter` to `status: "incomplete"` with `incomplete_details.reason = "content_filter"` in both non-streaming and synthesized streaming output (streaming terminates with `response.incomplete` and the message item marked `incomplete`, usage included; raw native Responses relay is untouched).
- **Responses request/response tolerance**: The Responses adapter omits `tool_choice` when the IR has no tools and renders `ToolChoice::Allowed` as the native `allowed_tools` object. `OpenAIResponsesResponse` tolerates Responses-compatible servers that omit non-essential fields (only `id`/`output` stay required; `billing`/`tool_choice` are optional and skipped on serialize), send `null` for defaulted fields, or a float `created_at` (Mistral); usage details also default so token accounting still flows.
- **openai_compat response tolerance**: Chat response/chunk/usage deserialization (`types/providers/tolerant.rs`) treats missing and `null` like the field default: only `choices` is required; `id`/`object`/`model` default to empty, `created` to 0 (integer or float), `index` to 0, `role` to "assistant", usage counts to 0 with `total_tokens` derived from prompt+completion when absent, and usage detail objects default per field. Message and delta `content` is `OpenAIResponseContent`: a string or an array of typed parts (text deltas take the joined `text` parts; other parts are left to dialect hooks). Message and delta `reasoning_content` may also arrive as a list of `{"content"|"text": ...}` blocks (some gateways in front of Gemini), whose texts are joined (`tolerant::string_or_text_blocks`). A non-streamed reply emits its reasoning before its text, so other formats render the thinking block or reasoning item first. A stream chunk that still fails to parse is skipped with a `tracing::warn!` (serde path only, no body content); a non-JSON or otherwise unusable 200 body keeps failing, with the serde path in the adapter error message and unchanged client rendering. The raw upstream JSON relay is untouched, so client-facing output does not change.
- **Tool choice `allowed_tools`**: Both skins map `allowed_tools` into `ToolChoice::Allowed { mode, tools }` (Chat nests it under `allowed_tools`, Responses carries `mode`/`tools` inline). OpenAI Chat and Responses adapters and Gemini emit their native allowed-tools form (Gemini maps `required` to `any`); Anthropic, OpenRouter (`OpenRouterDialect`) and Mistral (`MistralDialect`) have no native equivalent, so they filter the forwarded tool list to the allowed names and map `required` to `any`/`required`/`required` respectively (`auto` otherwise).
- **Skin routes**: Additional protocol routes are registered with `OmniferenceServer::add_skin_routes` or `OmniferenceServerBuilder::with_skin_routes`; do not add path sniffing for new protocols. Embedded hosts may pass `SkinRequestMetadata`, which handlers merge into `ChatRequestIR::metadata` before middleware execution.
- **Finish reasons**: Adapters surface non-default termination through the neutral `StreamEvent::Finish { reason: FinishReason }` (`Stop | Length | ToolCalls | ContentFilter`), emitted only when the provider reports a reason other than the implicit default (`stop`, or `tool_calls` via tool-call events); skins render it as the protocol finish reason in both streaming and non-streaming output.
- **Unsupported parameters**: Adapters reject request parameters the provider cannot honour with `AdapterError::Invalid` (rendered as 400 `invalid_request`) instead of silently dropping them: `n > 1` where the provider returns a single candidate (detect with `adapter::requests_multiple_candidates(&ir.metadata)`), and sampling fields with no provider equivalent (such as `logprobs` on Anthropic). Responses `n` arrives via flattened request extras and never reaches IR metadata, so the Responses skin rejects `n > 1` itself with the same 400.
- **Refusals and logprobs**: Anthropic `stop_reason: "refusal"` text is emitted as `RefusalDelta` in non-streaming responses; in streaming responses Anthropic sends text before `stop_reason`, so that text stays as `TextDelta` (only the `ContentFilter` finish reason is known at the end) to avoid buffering all text and losing streaming latency. Adapters surface provider refusals as `StreamEvent::RefusalDelta` (never `[Refusal]`-prefixed content) and provider logprobs payloads as `StreamEvent::Logprobs`; skins render them as the protocol `refusal`/`logprobs` fields in both streaming and non-streaming output (Chat message `refusal`/choice `logprobs`; Responses refusal content parts with `response.refusal.delta`/`response.refusal.done` events and `output_text` logprobs).
- **Reasoning continuity**: assistant reasoning travels as `ContentPart::Reasoning(ReasoningBlock)` in the IR and `StreamEvent::ReasoningBlock` on streams (alongside `ReasoningDelta` text). Each block keeps its provider `format` tag (`anthropic-claude-v1`, `google-gemini-v1`, `openai-responses-v1`, `unsigned` for plain text). Adapters capture signatures/opaque payloads (Anthropic `signature_delta` + `redacted_thinking`, Gemini thought signatures, Responses `encrypted_content`, OpenRouter `reasoning_details`, LiteLLM `thinking_blocks`) and replay a block only when its format matches the target provider: Anthropic emits thinking/redacted blocks first, then text/tool_use; Gemini emits Thought steps with signatures; the Responses provider emits input reasoning items and requests `include: ["reasoning.encrypted_content"]` when reasoning is active (preserved requests: only when the client sends `store:false`; rebuilt requests: when reasoning is configured or replayed). OpenRouter (Responses) replays every non-unsigned block as a `reasoning` input item with `format`, `signature` and its text as `reasoning_text` content, and reads OpenRouter's `format`/`signature` on output reasoning items back into blocks of that format (`ResponsesDialect::replays_reasoning`; any Responses item that carries `format` is read that way); openai_compat forwards unsigned text as `reasoning_content` and Anthropic-format blocks as `thinking_blocks`. Foreign-format blocks are silently dropped (empty details are skipped). The Chat skin writes `reasoning_details`, `thinking_blocks`, `reasoning_content`/`reasoning` (message and delta; streaming emits `delta.thinking_blocks` next to `delta.reasoning_details` for Anthropic-format blocks) and reads them with a precedence rule on input: `reasoning_details` is authoritative, `thinking_blocks` is used only when it yields no blocks, and `reasoning_content`/`reasoning` text only when neither does (they repeat the same text), with blocks deduplicated by (format, signature/data) so an echoed omniference reply never replays a block twice; the Responses skin renders native `reasoning` output items, putting an `omn1.`-prefixed base64 envelope (versioned JSON with format/kind/text/signature/data/id) in `encrypted_content` only when the client `include` requests it, and decodes that envelope (passing genuine OpenAI `encrypted_content` through) on input. The Responses adapter's preserved-request path drops `omn1.` reasoning input items before forwarding to OpenAI, except `openai-responses-v1` envelopes, which are unwrapped to their inner `data`/`id` (`ReasoningBlock::to_envelope`/`from_envelope` in `types/mod.rs`). In Responses streaming, the reasoning item is announced on the first `ReasoningDelta`, each delta is relayed as a `response.reasoning_summary_text.delta`, and the completed block closes the item with the full summary and any requested envelope.
- **Errors**: Preserve `AdapterError`/`InferenceError` categories through service and skin boundaries. `upstream::http_error` keeps the failed response's `retry-after`, `x-should-retry` and request ID (`request-id`, else `x-request-id`) as `UpstreamHints` on the `Provider` error, and every skin error handler sends them back on whatever status it renders (`skins::with_upstream_hints`; request ID as `x-request-id` on OpenAI skins, `request-id` on the Anthropic skin); provider rate-limit headers are never relayed. A body over a route's limit is 413 `request_too_large` (`SkinErrorHandler::handle_payload_too_large`, from `SkinAwareJson`). Upstream failures must not be converted into JSON-deserialization errors. Streaming failures are emitted as protocol error events. Redacted upstream messages are rendered for client-attributable 4xx (400/404/413/422/429, same status passed through); provider auth (401/403), billing (402), and 5xx failures stay normalized as 502 with no upstream text. All adapters build non-success-response errors through `upstream::http_error`, which parses the upstream status/error fields, including error JSON in SSE-framed (`data:`) bodies via `SseParser`, and redacts provider credentials before anything is logged or rendered.
- **Server safety**: The standalone binary binds to loopback by default. Public listeners are rejected unless bearer authentication is configured or unauthenticated public access is explicitly allowed. `ServerSecurityConfig` owns bearer authentication, body size, concurrency, request-start timeout, and explicit permissive-CORS opt-in.
- **Secrets**: Provider credentials and extra-header values are redacted from `Debug` and excluded from serialization. Do not add request or trace paths that serialize provider credentials.
- **Catalog**: Model limits, modalities, capabilities, reasoning budget ranges, aliases, and pricing come from the committed `catalog/.snapshot/api.json` plus TOML overrides in `catalog/` or `OMNIFERENCE_CATALOG_OVERRIDE_DIR`. Do not add heuristic model-id guessing in adapters.
- **Vendor profiles** (guide: `docs/vendor-profiles.md`; keep it in step with this paragraph): a provider's vendor (Mistral, DeepSeek, Z.AI, ...) is separate from its protocol (`ProviderKind`/adapter). `OmniferenceService::register_provider` resolves it once through `catalog::providers::resolve_provider` and stores the result in `ProviderConfig::resolved_profile` (library users who build a `ModelRef` by hand call it themselves): `catalog_provider_slug` if set, else the one profile whose `hosts` contain the base URL host, else none (generic behaviour; FakeUpstream is localhost, so cases resolve nothing unless `case.toml` sets `vendor`). Never pick an adapter by host. `ProviderConfig::vendor_slug()` (configured or resolved) is the catalog provider slug. Profiles: `catalog/providers/<slug>.toml` (`slug` = file name, `hosts`, `dialect`, `[request.chat]`/`[request.responses]`/`[request.messages]` each with `rename`/`reject`/`drop`/`default`, `[headers]` shared by all protocols, `deny_unknown_fields`, so a flat `[request]` with rule keys fails to load), layered by `OMNIFERENCE_CATALOG_OVERRIDE_DIR/providers/<slug>.toml` and the inline `ProviderConfig::profile` (no `slug`/`hosts`); each layer overrides only what it sets (`rename`, `default`, `headers` key by key; each protocol table on its own). An invalid profile fails registration with `ProviderRegistrationError::InvalidProfile`. Request rules (`adapters/request_rules.rs`) are JSON-level, dotted paths with `[]` for every array item (no `*`, no indexes, missing path = no-op); `rename` keeps the parent path (moving a value is a dialect's job), both keys set and a set `reject` field are 400 `invalid_request`. `OpenAIAdapter` (Chat), `OpenAIResponsesAdapter` and `AnthropicAdapter` apply profiles, each only its own protocol's rules (`ResolvedProfile::rules_for(Protocol)`): built request → that protocol's dialect `patch_request` → `extra_body` merge → rules → send; profile headers yield to endpoint `extra_headers` (`adapter::vendor_and_endpoint_headers`). `OpenRouterAdapter` runs chat through the Responses adapter, so `[request.responses]` rules and headers apply to it; its dialect is the Responses part of the profile's dialect, else `OpenRouterDialect` (`catalog/providers/openrouter.toml`: host `openrouter.ai`, dialect `openrouter`). Every `OpenRouterAdapter` call (chat, discovery, images) adds the fixed attribution headers `HTTP-Referer` (`CARGO_PKG_REPOSITORY`) and `X-Title: Omniference` unless the endpoint `extra_headers` or, for chat, the profile `[headers]` set that name. Gemini ignores profiles. On the Anthropic adapter, a raw-forwarded Messages body (Anthropic Messages skin) gets the `[request.messages]` rules and headers but no dialect `patch_request`. Dialect traits (`adapters/dialects/`): `ChatDialect` (typed `OpenAIChatRequest`, plus reasoning read hooks), `ResponsesDialect` (`serde_json::Value`, plus `replays_reasoning` for which earlier reasoning blocks go back and `usage_cost` for a provider-reported cost in `usage`) and `MessagesDialect` (typed `AnthropicMessagesRequest`, `patch_request` only); default methods are the base behaviour; add a hook only for a real vendor difference, one named difference per hook. A vendor has one `dialect` name; `DIALECTS` maps it to a `Dialect` with optional `chat`/`responses`/`messages` parts, a missing part is the base behaviour and an unknown name fails registration. Each dialect behaviour gets a vendor-scoped case (`case.toml` `vendor = "<slug>"`, e.g. `openai_compat/mistral_allowed_tools`, `openai_responses/mistral_store`). `MistralDialect` maps `allowed_tools` (`patch_request`) and reads Mistral's `{"type":"thinking","thinking":[{"type":"text",...}]}` content parts as reasoning (`delta_reasoning`/`message_reasoning`, verified live on `mistral-small-latest`; cases `mistral_reasoning`, `mistral_reasoning_nonstreaming`). The OpenAI Chat skin still relays Mistral's raw parts to Chat clients. On Responses, `MistralDialect` maps `allowed_tools` the same way (keeps the tools listed in `tool_choice.tools`, sends `required` or `auto`) and refuses `store`, `background`, `truncation`, `top_logprobs` and `n` unless `false`/`false`/`"disabled"`/`0`/`1` (Mistral's Responses API is stateless and silently ignores `n > 1`), and `mistral.toml` `[request.responses]` rejects `previous_response_id`, `conversation`, `moderation` and `prompt`; live targets `mistral` (Chat) and `mistral_responses`. `OpenRouterDialect` adds reasoning `max_tokens` (from `budget_tokens`), `provider` routing, `stop` and penalties when the request lacks them, maps `allowed_tools`, replays every signed reasoning format and reads `usage.cost` (else the upstream cost) as `StreamEvent::Cost`. `CortecsDialect` (`cortecs.toml`: host `api.cortecs.ai`) maps provider routing: `only` → `allowed_providers`, `order` → `allowed_providers` in that order (filtered by and followed by the rest of `only`) plus `provider_order: "custom"`; Cortecs never falls back beyond the list, and an `only` that leaves none is refused. `catalog::fetch_cortecs_models` reads `/v1/models?extended=true` (per-provider `providers_details`; prices per 1M tokens in `pricing.currency`, EUR today; `metrics.latency`/`ttft` in seconds). OpenRouter's Responses API is stateless (`store` false, no `previous_response_id`); a client that sends either gets OpenRouter's 400. The generic OpenRouter cases are recorded live from OpenRouter's Responses API (reasoning streams as `response.reasoning_text.delta`, reasoning items carry `format`/`signature`, `usage.cost` with `cost_details.upstream_inference_input_cost`/`_output_cost`); the signed Anthropic round trip is verified live on `anthropic/claude-haiku-5.5` (`live_reasoning::openrouter_*`). Unsupported reasoning efforts are per-model catalog facts (models.dev `reasoning_options`), not vendor quirks: the provider's 400 passes through and no dialect rewrites efforts. Tolerant response parsing stays generic; profiles and dialects are for what we send and for fields vendors interpret differently.
- **Host pricing overrides**: `Catalog::set_pricing_override`, `clear_pricing_override` and `replace_pricing_overrides` hold a host's own prices (such as admin-set prices) keyed by `ProviderConfig::name` and the exact model ID, never by catalog slug, so providers of the same kind and dated model variants keep their own prices. They win over every other layer; `catalog_pricing` returns the price without them.
- **Dynamic pricing**: `ModelPricing` has base rates plus `tiers` (context), `service_tiers` (name → `ServiceTierPricing`: partial `PricingRates` plus that tier's own context tiers) and `windows` (`TimeWindow`: `days`, `HH:MM` `start` inclusive/`end` exclusive, `UTC` or IANA `timezone`, partial `rates`; `end <= start` wraps midnight and `days` names the start day). `ModelPricing::resolve` applies base → context tier → service tier → its context tier → windows in list order, each layer overriding only the rates it sets; tiers cover audio rates too. New fields are `#[serde(default)]` so stored `ModelPricing` JSON without them still loads. `cost::compute(pricing, usage, started_at, service_tier)` matches windows against the request **start** time, never the end. `CostMiddleware` records `CostRecord::started_at` and `CostRecord::service_tier` (the tier from `StreamEvent::OpenAIMetadata`, else the requested `service_tier` metadata, ignoring `auto`). `ContextTier::min_context_tokens` is inclusive; models.dev `size` and OpenRouter `min_prompt_tokens` mean "over N" and are stored as `N + 1`. models.dev `context_over_200k` is read only when `cost.tiers` is absent; unknown tier types are skipped and logged once. OpenRouter `pricing.overrides` become `tiers`, and `endpoint_pricing` adds sibling endpoints with a `service_tier` from the same provider as `service_tiers`. `ModelPricing::validate`/`TimeWindow::validate` check rates, thresholds, times and timezones.
- **Catalog lifecycle**: Each service owns a shared catalog refresh runtime. Dropping the final service clone cancels its refresh task; refresh calls use the shared HTTP client and a bounded timeout.
- **Reasoning budgets**: `ReasoningBudget` is the canonical catalog range on `DiscoveredModel`/`CatalogEntry`. Fixed `ModelCapabilities::ReasoningBudgetTokens_*` values are legacy projections and must be derived from the structured range so catalog layers cannot disagree. A higher catalog layer with `reasoning = false` clears inherited reasoning metadata.
- **Anthropic thinking**: Claude 4.6+ uses adaptive thinking. A reasoning effort sends `thinking: {"type":"adaptive"}` and `output_config.effort` (merged with any structured-output `format` in the same `output_config` object); `minimal` maps to `low`, `none` omits both, and unknown efforts are 400 `AdapterError::Invalid`. Explicit `budget_tokens` wins over effort and is forwarded verbatim as `thinking: {type:"enabled", budget_tokens}` (manual mode, no derivation or clamping, effort not sent). No own temperature/top_p/top_k/forced-tool_choice validation: those are forwarded, and Anthropic's client-attributable 4xx pass through redacted. Default `max_tokens`: 64000 in all cases when the client sends none (no thinking, adaptive thinking, or explicit `budget_tokens`; if `budget_tokens` >= 64000 Anthropic rejects the request, no own validation is added), because 64000 is the lowest max output among currently active Claude models (Haiku/Sonnet/Opus 4.5; all 4.6+ allow 128000, per `catalog/.snapshot/api.json`). A client `max_tokens` is always preserved. Thinking and `redacted_thinking` blocks are captured and replayed as described under Reasoning continuity; unknown blocks parse but emit nothing. `ToolChoice::None` is sent as `{"type":"none"}`, and `tool_choice` is omitted when no tools are sent. Streaming usage takes the cumulative `input_tokens`/cache counts of `message_delta` over `message_start` when present. Model discovery pages `GET /v1/models` with `limit=1000` and `after_id` while `has_more`. Consecutive assistant (and tool-result) IR messages are coalesced in the Anthropic adapter so a thinking block shares one assistant message with its text/tool_use blocks, and Responses input items for one assistant turn are already grouped into a single IR message by the Responses skin.
- **Anthropic files and tool results**: IR-built requests send `ContentPart::File` as a `document` block (base64 from a `data:<type>;base64,` `file_data`, or a URL `file_id`; plain file IDs are 400 `AdapterError::Invalid`) and each Tool message as one `tool_result` whose `content` is a string for a single text part, else text, image and document blocks. The Chat skin keeps image and file parts in tool messages; the Responses skin reads `input_file` as `ContentPart::File` (`file_url` goes into `file_id`) and accepts `function_call_output.output` as a string or content parts. The Anthropic Messages skin turns `tool_result` text, image and `document` blocks into Tool message parts. OpenAI Chat tool messages carry text only, so openai_compat moves a run of tool messages' images, audio and files into one user message right after it (`adapter::hoist_tool_media`, each call's attachments introduced by its call ID); preserved OpenAI Chat requests are forwarded unchanged. The Responses adapter sends tool results with media as `function_call_output` content parts and files as `input_file` (a URL `file_id` as `file_url`); Gemini sends text and images as function results and rejects files with a 400. OpenRouter, on the Responses adapter, sends them as `function_call_output` content parts like Responses.
- **Deferred tools** (Anthropic tool search): `ToolSpec::JsonSchema::defer_loading` and `ContentPart::ToolReference { name }` carry them through the IR. The Responses skin reads `defer_loading` on function tools, `tool_reference` parts in `function_call_output.output` (→ `ToolReference` in the Tool message) and `additional_tools` input items (their tools are declared up front as deferred tools, and the item becomes a System message of `ToolReference`s where it stands). The Anthropic adapter sends `defer_loading`, `tool_reference` blocks inside the `tool_result`, and System-message references as `tool_addition` blocks in a mid-conversation `system` message with the `mid-conversation-tool-changes-2026-07-01` beta; references before the first message instead make those tools non-deferred. The Anthropic Messages skin keeps `defer_loading` for non-Anthropic providers. Every other adapter rejects tool references with 400 (`adapter::reject_tool_references`; Gemini its own error), never drops them. A Responses body the typed request cannot read is forwarded unchanged to `OpenAI`/`OpenRouter` providers only and is 400 `invalid_request` elsewhere. Not yet supported on the OpenAI Chat skin (HEN-125).
- **Anthropic prompt caching**: the adapter sends top-level `cache_control: {"type": "ephemeral"}` (5-minute TTL) by default. Per-request control travels on the typed IR field `ChatRequestIR::anthropic_cache` (`AnthropicCacheConfig`), populated from the documented `anthropic_cache` request extra (`"disabled"`, `"5m"`, `"1h"`, boolean, or `{"enabled": ..., "ttl": ...}` object). Disabled omits `cache_control` so no cache write is billed.
- **Costs**: Token-billed provider costs are computed centrally by `CostMiddleware` from stream usage and catalog pricing, including streams that end without `StreamEvent::Done`. Provider-reported `StreamEvent::Cost` stays authoritative and is held until Done, Error, EOF, or Drop so the single `CostRecord` handed to `CostSink::record_with_context`/`record_usage` carries `finish_reason` (last `Finish` event; `Done` without one means `ToolCalls` after a tool call, else `Stop`; none for Error/EOF/Drop) and `time_to_first_token` (first text, reasoning, refusal or tool-call event).
- **Terminal usage**: `CostSink::terminal_usage` reports observed usage once at Done, Error, EOF, or Drop independently of monetary finalization. ProviderReported cost must not suppress terminal accounting. `QueuedCostSink` forwards terminal usage through a distinct queue message to `AsyncCostSink::terminal_usage`, independently of cost records; regression coverage lives in `tests/unit/cost.rs`.
- **Gateway protocol metadata**: `skins/limits.rs` renders OpenAI rate-limit and request-ID headers from neutral values. `openai_stream_error_event` owns SSE error framing. Raw upstream error objects/messages/codes must be normalized before public rendering, except redacted upstream message/type/param/code for client-attributable 4xx (400/404/413/422/429), which pass through to the client. Contract tests live in `tests/unit/gateway_protocol.rs`.
- **Cost recording**: HTTP and library requests share the service middleware chain. Cost is recorded through a non-blocking `CostSink` before terminal events and on stream drop when usage is available; wrap asynchronous persistence with `QueuedCostSink` and use the service cost-sink constructors for durable host accounting.
- **Model identity**: `DiscoveredModel.id` is `<normalized-provider-name>/<provider-native-model-id>` and `DiscoveredModel.name` is display-only. Routing must strip the provider prefix from `id`; never send `name` upstream. Provider lookup is an exact case-insensitive name match and must not fall back by provider kind. Bare native model IDs resolve only when exactly one provider exposes them.
- **Discovery**: Service-level model discovery snapshots provider configs, performs provider calls with bounded concurrency without holding the provider manager lock, then reacquires the write lock only to update discovered models.
- **Discovery results**: Detailed discovery methods return a `DiscoveryReport` containing committed models and per-provider failures; legacy discovery methods keep returning model vectors and log failures. Disabled providers are skipped, and results are committed only when the provider configuration generation still matches the discovery snapshot.
- **Provider registration**: Enabled provider reconfiguration is transactional. Discover against the proposed configuration while the prior provider and model cache remain active, then replace both atomically; a failed or superseded registration returns a typed `ProviderRegistrationError` without disturbing active state.
- **Server builder**: `OmniferenceServerBuilder::with_provider` is async and must successfully register the provider before `build`; never accept and silently defer or discard provider configuration.
- **Model listing**: HTTP model-list endpoints read the authoritative provider-manager cache and do not perform provider network calls. Refresh through provider registration or the explicit service discovery APIs.
